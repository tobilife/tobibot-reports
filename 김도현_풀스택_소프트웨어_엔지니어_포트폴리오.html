Engineering Workflow

엔지니어링 철학 및 실무 라이프사이클

코드를 작성하기 전부터 프로덕션 배포 후 모니터링까지, 문제를 구조적으로 해결하는 저만의 3단계 엔지니어링 프레임워크입니다.

PHASE 1.1

RFC & 기술 명세서 작성

코드 한 줄을 적기 전 시스템 아키텍처 다이어그램, 데이터 스키마, 엣지 케이스를 RFC 문서로 작성해 팀과 먼저 싱크를 맞춥니다.

PHASE 1.2

도메인 모델 분리

비즈니스 로직과 UI/인프라 의존성을 엄격히 격리하여 향후 라이브러리 교체나 스키마 변경에도 핵심 도메인을 온전히 보호합니다.

PHASE 1.3

성능 예산(Budget) 수립

번들 사이즈 상한선(초기 로딩 200KB 이하), API 응답 P95 200ms 미만 등 계측 가능한 기준치를 미리 규정하고 착수합니다.

PHASE 2.1

타입 안전성 100%

TypeScript 엄격 모드(strict: true)와 Zod 런타임 검증을 결합하여 경계면(boundary)에서 잘못된 데이터 유입을 원천 차단합니다.

PHASE 2.2

테스트 피라미드 준수

순수 비즈니스 로직 단위 테스트와 중요 결제/인증 흐름에 대한 E2E(Playwright) 테스트를 통합하여 회귀 버그를 방지합니다.

PHASE 2.3

선언형 상태 관리

불필요한 리렌더링을 유발하는 글로벌 상태 남용을 지양하고, 서버 상태(TanStack Query)와 UI 상태를 명확히 분리합니다.

PHASE 3.1

구조화된 로깅 & 트레이싱

JSON 포맷의 표준 로깅과 OpenTelemetry 트레이싱 ID를 부여해 분산 서비스 간 장애 추적 시간을 분 단위로 단축합니다.

PHASE 3.2

점진적 카나리 배포

새 버전 출시 시 5% 트래픽부터 단계적으로 라우팅하며 에러율 스파이크 감지 시 즉각 자동 롤백을 수행하도록 자동화합니다.

PHASE 3.3

주기적 테크 빚(Debt) 상환

스프린트마다 일정 비율을 레거시 라이브러리 업그레이드와 미사용 코드 제거에 할당하여 장기적인 유지보수 비용을 낮춥니다.
